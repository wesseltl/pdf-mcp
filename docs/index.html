Reliability loop

Define the contract, then measure it.

  1. DefineName canonical fields, aliases, types, and rejection rules for one recurring layout.
  2. CheckBuild expected rows from an accepted sample set and preserve source evidence.
  3. MeasureReport exact field, record, and review-routing performance against that ground truth.
  4. RunAgents automate accepted results and route every exception to review.

Good fit

Recurring tables with a stable business meaning.

  • Lab reports and certificates of analysis
  • Vendor statements and operational reports with repeated layouts
  • Workflows with named fields, types, and acceptance rules
  • Processes where exceptions can be routed to a reviewer

Out of scope

No OCR or sensitive health data.

  • Scanned or image-only PDFs
  • Handwriting, charts, images, and password-protected files
  • Patient data or other special-category personal data
  • Manual data entry when no usable table is detected
  • Accuracy claims for layouts absent from the evaluation set
  • Production hosting or ongoing integrations in the fixed-price pilot

Choose the boundary

The parser is open. Reliability is workflow-specific.

pdf-mcp is an MIT-licensed local MCP server with no uploads or telemetry. Customer profiles and evaluation sets stay private unless their owner chooses otherwise. The separate hosted beta is proprietary on the server side and measures bounded operational usage. The paid pilot covers the document-specific mapping, ground truth, measurement, and review policy that a generic parser cannot provide.
